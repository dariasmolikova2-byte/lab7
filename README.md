На основі спроектованої логічної моделі сформовано такі фізичні бізнес-правила із застосуванням обмежень цілісності:
1.Обмеження PRIMARY KEY та AUTOINCREMENT (Унікальність): Кожна сутність (Група, Кафедра, Предмет тощо) має цифровий удентифікатор, який є унікальним для кожного запису та генерується автоматично.
2.Обмеження NOT NULL (Обов'язковість заповнення): Текстові поля, такі як назва групи, повне ім'я викладача, назва предмету чи корпусу, є обов'язковими для заповнення і не можуть бути порожніми.
3.Обмеження CHECK (Діапазон значень): Номер курсу для сутності UniversityGroup обмежений діапазоном від 1 до 6.
4.Обмеження FOREIGN KEY (Цілісність зв'язків): Центральна таблиця фактів Lesson («Заняття») містить 7 зовнішніх ключів, які суворо посилаються на існуючі записи у відповідних таблицях-довідниках, що запобігає появі неіснуючих уроків або груп у розкладі.
